# Reporting Convention for Ethereum Dropper Project

## Stage Numbering
- Stages are numbered sequentially starting from 0 for the initial bootstrap.
- Each stage represents a major milestone in the project as agreed upon with the supervisor.
- Stage numbers are continuous and do not skip numbers. If a stage is subdivided, it is still counted as one stage.
- Task tracker IDs (e.g., #17) are distinct from stage numbers and are used for internal task management within a stage or for specific sub-tasks that do not constitute a full stage.

## Content Guidelines
- Reports sent to the supervisor should contain only information relevant to the research progress.
- Exclude environment-specific details, such as local Docker container issues, personal laptop problems, or transient development hiccups.
- Focus on: objectives met, components created/modified, build status, verification steps, and any deviations from the plan.
- Use plain Markdown without raw HTML entities. Use Markdown syntax for line breaks and formatting.

## Document Structure for Stage Completion Reports
1. **Overview**: Brief summary of the project status.
2. **Completed Stages**: Table listing each stage, its title, objective, and key deliverables.
3. **Files Created/Modified**: Summary of significant file changes.
4. **Current State**: Status of tools (build success, functionality).
5. **Current Task**: Description of any in-progress task (with its ID).
6. **Next Steps**: Outline of the immediate next steps as directed by the supervisor.
7. **How to Proceed**: Instructions for the supervisor on how to provide feedback or approval.

## Example of a Good Report Entry
- Stage 0: Repository Bootstrap & Toolchain Verification
  - Objective: Set up dev environment, verify Go & dependencies, initialize repo.
  - Key Deliverables: Go installed, `go.mod` with dependencies, basic folder layout.

This convention ensures reports are clear, consistent, and focused on research progress.
